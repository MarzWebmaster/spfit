# API Documentation: API Key Management

## Overview

API Keys allow external systems to authenticate with SPFIT without requiring user credentials. Keys are generated by authenticated admins and can be used programmatically via the x-api-key header.

## Base URL
/api/api-keys

## Authentication

All API key endpoints require either:
- JWT Bearer token (for admin users) with permission settings:manage:api
- Existing API key (for accessing other endpoints)

## Endpoints

### 1. List All API Keys
GET /api/api-keys

Lists all API keys (without showing raw key material). Returns id, name, key_prefix, status, timestamps, and creator info.

### 2. Create New API Key
POST /api/api-keys

Generates a new API key. The raw key is returned once only in the response. Store it securely - it cannot be retrieved later.

### 3. Revoke API Key
PATCH /api/api-keys/:id/revoke

Marks an API key as revoked. The key can no longer be used for authentication but still exists in the database for audit purposes.

### 4. Delete API Key
DELETE /api/api-keys/:id

Permanently deletes an API key from the database.

## Using API Keys for External Access

Once created, external systems can access any API endpoint by including the key in the request header:

x-api-key: spfit_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

### Scope & Permissions

API keys are treated as virtual Admin users internally. This means:
- All endpoints that require Admin role or settings:manage: permissions are automatically accessible
- No per-key permission granularity yet (all keys are full-access)
- Keys are NOT tied to any specific user (they are system-level credentials)

### Key Tracking

Every API key call updates the last_used_at timestamp on the key record, enabling audit and monitoring of key usage patterns.

### Security Best Practices

1. Treat API keys like passwords - never expose them in client-side code or public repos
2. Use environment variables in external systems to store keys securely
3. Rotate keys periodically - delete old keys and create new ones for long-lived integrations
4. Revoke immediately if a key is compromised or no longer needed

### Error Responses

| Status | Condition | Response Body |
|--------|-----------|---------------|
| 401 | Missing or invalid API key | Invalid or revoked API key |
| 401 | API key expired | API key has expired |
